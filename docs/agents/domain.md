# Domain docs

Use a single-context layout: keep the glossary at the repository root and architecture decisions in `docs/adr/`.

Before work, read `GLOSSARY.md` if it exists and relevant decisions under `docs/adr/`. If either is absent, proceed without treating its absence as a problem.

Use glossary terms consistently in issues, design notes, code, and tests. If a needed term is missing, record the gap instead of inventing competing terminology. Surface conflicts with existing ADRs before changing the affected design.
